# 知识卡片生成

把一篇文章拆成一组可以独立复习的知识卡片。

## 输入

支持：

- 对话中直接粘贴的正文。
- 本地 `.md` / `.txt` 文件，用 Read 工具读取，不修改原文件。
- 中英文或混排文本；卡片语言跟随原文。

不支持（用一句话说明边界并给出替代做法，不要假装能处理）：

- 网页抓取、URL 链接：请用户粘贴正文，或另存为 `.md` / `.txt`。
- PDF、Word、PPT、图片 OCR：请用户先转成纯文本。
- Anki / apkg 等卡片软件格式导出。
- 图形界面或交互式应用。

文件读出来是乱码时，说明编码不是 UTF-8，请用户另存为 UTF-8 或直接粘贴正文；不要靠猜测修补乱码内容。

## 输出格式

默认直接在对话中输出 Markdown，不创建文件。用户明确说“保存 / 导出 / 写成文件”时，写到当前工作目录的 `<源文件名>-cards.md`，不覆盖输入文件。

输出先写一行 `共 N 张卡片`；少于 5 张时补充一句原因。随后逐张输出：

```markdown
### 1. 卡片标题

**核心知识：** 一句话说明这个知识点是什么。

**简明解释：** 1-3 句，说明它为什么成立、怎么起作用或适用条件。原文依据有限时，可以只交代它与其他要点的关系或它在原文中的位置，不要为了凑长度补充原文没有的内容。

**例子：** 原文中的具体实例；原文没有例子时改用下面的自测。

**自测：** 一个问题。
**参考答案：** 依据原文作答的要点。
```

每张卡必须有标题、核心知识、简明解释，以及“例子”或“自测”中的至少一项。不要写开场白、总结段落、学习建议或延伸阅读。

## 质量规则

以下规则优先于数量要求。

1. **只提真正重要的知识。** 保留定义、机制或原理、关键方法或步骤、重要结论、适用条件、常见误区。删除背景铺垫、客套话、重复修辞、与主题无关的举例。
2. **一张卡片只讲一个知识点。** 标题就是该知识点。若卡片里出现“另外 / 同时 / 此外”引出第二件事，拆成两张卡或删掉次要内容。
   - 回答同一个问题的并列项可以放在同一张卡里，例如“有哪些优势”“需要满足哪些性能”“有哪些常见错误”。
   - 不同问题不要混在一张卡里，例如把“优势”和“限制”写进同一张卡。
   - 判断知识点是否独立：能否单独写成一道自测题，且答案不依赖另一张卡。
3. **删除重复。** 同一知识点只保留信息最完整的一处；换句话说的重复表述合并，不重复成卡。
4. **不能编造。** 数字、名称、因果、结论、例子都必须能在原文找到依据。原文没说的不补全、不推测、不引用外部常识。拿不准的内容直接不写。
   - 改写只能压缩或重组原文，不能补充原文没有的因果、机制或技术解释；解释写不深时，就贴近原文表述，不要为了显得专业而加内容。
   - 不要把原文分开陈述的条件和结果合并成“都会 / 都导致”的概括；原文分别对应什么，就分别写什么。
   - 例子优先取原文已有实例；原文没有例子时写“自测”，不要自己造例子，以免引入原文没有的信息。
   - 自测的参考答案也必须能在原文定位。
5. **信息不足时不凑数。** 目标是 5-8 张；真正独立且重要的知识点不足 5 个时，输出实际数量（可能只有 2-4 张），并说明“原文可用知识点不足，未凑数”。超过 8 个时合并相近知识点或舍弃次要内容，不要靠压缩每张卡字数来硬塞。
6. **禁止凑数手段。** 不拆一个知识点、不换说法重复、不加“背景卡 / 总结卡 / 延伸卡”。
7. **顺序跟随原文逻辑。** 原文是并列罗列时，按重要程度或原文顺序排列。

## 不确定与缺失信息

- 原文出现“好像 / 据说 / 可能 / 记不清 / ？”等不确定表述时，不要升级成确定结论。去掉不确定部分后没有可用知识，就不成卡。
- 原文只说“有规定 / 有影响 / 有要求”但没给具体内容时，不要补数值、标准号或做法。可以只写原文确认的那一层，或直接不写。
- 原文前后矛盾时，不替作者裁决，取能明确成立的部分；无法判断就不写。

## 工作流

1. 获取正文；确认主题和大致篇幅。输入是链接、PDF 等不支持的形式时，先按“输入”一节处理。
2. 通读全文，在内部列出候选知识点（不要输出草稿）。
3. 按“是否重要、是否独立、是否有原文依据”筛选；合并重复、拆开复合点。
4. 确定卡片集合：优先 5-8 张；知识点不够就少输出，太多就合并或舍弃。
5. 按模板逐张写卡。
6. 用下面的清单自检后再输出。

## 按文本类型取舍

- **概念科普类：** 优先定义、机制、关键对比、适用条件。
- **操作教程类：** 一张卡对应一个可独立执行的关键步骤或关键概念；琐碎操作（如“打开软件”）合并，不单独成卡。
- **观点评论类：** 卡片写“作者主张 + 原文依据”，不要把观点写成客观事实；没有依据的主张不单独成卡。
- **信息少或结构混乱的文本：** 只保留能确认的独立知识点，不替作者补逻辑，不把一句话拆成多张卡。

## 输出前自检

- [ ] 每张卡只有一个知识点，标题能概括它
- [ ] 所有事实、数字、因果都能在原文定位
- [ ] 没有两张卡讲同一件事
- [ ] 卡片数量有依据：没有为凑 5 张硬拆，也没有把两个独立重点强行合并
- [ ] 每张卡都有例子或自测（自测含参考答案）
- [ ] 没有加入原文之外的例子、数据、背景
- [ ] 信息不足时已如实说明原因

## 示例

输入（约 90 字，含 3 个独立知识点）：

> 光合作用是绿色植物利用光能，把二氧化碳和水转化成有机物并释放氧气的过程。它发生在叶绿体中，叶绿素负责吸收光能。光合作用为几乎所有的生态系统提供能量来源。

输出：

共 3 张卡片（原文可用知识点不足 5 个，未凑数）

### 1. 光合作用的定义

**核心知识：** 光合作用是绿色植物利用光能，把二氧化碳和水转化成有机物并释放氧气的过程。

**简明解释：** 这句话同时交代了条件（光能）、原料（二氧化碳和水）和产物（有机物、氧气）。

**自测：** 光合作用的原料和产物分别是什么？
**参考答案：** 原料是二氧化碳和水，产物是有机物和氧气。

### 2. 光合作用的发生场所

**核心知识：** 光合作用发生在叶绿体中，由叶绿素吸收光能。

**简明解释：** 叶绿体是场所，叶绿素负责吸收光能，两者分工不同。

**自测：** 叶绿体和叶绿素在光合作用中分别起什么作用？
**参考答案：** 叶绿体是发生场所，叶绿素负责吸收光能。

### 3. 光合作用的生态意义

**核心知识：** 光合作用为几乎所有的生态系统提供能量来源。

**简明解释：** 这是原文对光合作用地位的直接结论，范围限定为“几乎所有的生态系统”。

**自测：** 原文如何描述光合作用对生态系统的作用？
**参考答案：** 它为几乎所有的生态系统提供能量来源。
